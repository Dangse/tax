# 워크샵 결과물 발표 — 업로드 기능 설치 안내

직원이 GitHub를 거치지 않고, **이름 · 제목을 넣고 HTML 파일을 올리면 바로 목록에 뜨게** 하는 설정입니다.
회사 구글 계정 하나만 있으면 되고, 비용은 들지 않습니다.

올리는 방법은 두 가지이고, **둘 중 하나만** 하시면 됩니다.

- **HTML 파일 올리기** — 만든 파일을 그대로 업로드
- **링크 주소 넣기** — 구글 슬라이드·문서, 노션, 유튜브 등 웹 주소를 등록

- 올라온 HTML 파일 → 구글 드라이브 폴더 `워크샵 결과물 발표`
- 목록(누가 · 무엇을 · 언제) → 구글 스프레드시트 `워크샵 결과물 발표 목록`

한 번만 설정하면 그 뒤로는 직원들이 웹페이지에서만 작업합니다.

---

## 1. 구글 Apps Script 프로젝트 만들기

1. **회사 구글 계정으로 로그인**한 상태에서 <https://script.google.com> 접속
2. 왼쪽 위 **`+ 새 프로젝트`** 클릭
3. 프로젝트 이름을 `워크샵 결과물 발표`로 변경 (왼쪽 위 "제목 없는 프로젝트" 클릭)

## 2. 코드 붙여넣기

1. 가운데 편집기에 있던 `function myFunction() {}` 를 **전부 지우기**
2. 이 저장소의 [`scripts/워크샵발표_업로드_AppsScript.gs`](워크샵발표_업로드_AppsScript.gs) 파일 내용을 **전부 복사해서 붙여넣기**
3. 저장 (Ctrl + S)

## 3. 최초 1회 실행 — 폴더 · 시트 자동 생성

1. 편집기 위쪽 함수 선택 상자에서 **`초기설정`** 선택
2. **`▶ 실행`** 클릭
3. 권한 요청 창이 뜹니다 → `권한 검토` → 계정 선택 →
   "이 앱은 확인되지 않았습니다" 경고가 나오면 **`고급`** → **`워크샵 결과물 발표(안전하지 않음)으로 이동`** → **`허용`**
   > 직접 만든 스크립트라 구글 검수를 안 거쳐서 나오는 안내입니다. 정상입니다.
4. 실행이 끝나면 아래 **실행 로그**에 드라이브 폴더 주소와 시트 주소가 찍힙니다. (나중에 파일·목록을 직접 볼 때 씁니다)

## 4. 웹 앱으로 배포

1. 오른쪽 위 **`배포`** → **`새 배포`**
2. 왼쪽 톱니바퀴(유형 선택) → **`웹 앱`** 선택
3. 아래처럼 설정
   | 항목 | 값 |
   |---|---|
   | 설명 | `워크샵 발표 업로드` (아무거나) |
   | 다음 사용자로 실행 | **나** |
   | 액세스 권한이 있는 사용자 | **모든 사용자** |
4. **`배포`** 클릭
5. 나오는 **웹 앱 URL**을 복사합니다. `https://script.google.com/macros/s/AKfy........./exec` 형태입니다.

> ⚠️ "액세스 권한이 있는 사용자"를 **모든 사용자**로 해야 직원들이 로그인 없이 쓸 수 있습니다.
> 파일 자체는 회사 드라이브에 있고, 목록에 등록된 파일만 열람되며, 업로드·삭제는 비밀번호(`0625`)를 통과해야 가능합니다.

### 주소로 설정이 맞는지 알아보는 법

Workspace 계정(taxdh.net)은 배포 후 이런 주소가 나올 수 있습니다.

```
https://script.google.com/a/macros/taxdh.net/s/AKfyc...../exec   ← /a/macros/도메인/ 이 붙은 형태
https://script.google.com/macros/s/AKfyc...../exec               ← 홈페이지에는 이 형태를 사용
```

`/a/macros/도메인/` 부분을 빼도 같은 앱입니다. **홈페이지 코드에는 짧은 형태를 넣으세요.**

접근 설정이 맞는지는 주소창에 `주소?action=list` 를 붙여 **시크릿 창**에서 열어 확인합니다.

- `{"ok":true,"items":[...]}` 가 보이면 → 정상 (모든 사용자)
- 구글 **로그인 화면**으로 넘어가면 → 아직 "나만" 또는 "조직 내 사용자" 상태입니다. 아래 "코드를 고친 뒤에는" 항목의 방법으로 액세스를 바꿔주세요.

## 5. 홈페이지에 주소 연결

두 가지 방법 중 하나입니다.

**(A) 코드에 넣기 — 권장, 모든 직원에게 한 번에 적용**

[`내부결재문서/워크샵결과물발표.html`](../내부결재문서/워크샵결과물발표.html) 안의 아래 줄을 찾아

```js
const API_URL = "";
```

복사한 주소를 넣고 저장 · 커밋합니다.

```js
const API_URL = "https://script.google.com/macros/s/AKfy........./exec";
```

**(B) 화면에서 임시로 넣기 — 내 브라우저에서만 적용**

`워크샵 결과물 발표` 페이지를 열면 위쪽에 노란 안내 상자가 뜹니다.
거기에 주소를 붙여넣고 **연결**을 누르면 그 브라우저에서만 바로 동작합니다. (테스트용)

## 사용 방법 (직원용)

1. 홈 → **내부결재문서** (비밀번호 `0625`) → **워크샵 발표**
2. 위쪽 **발표 자료 올리기** 에 이름 · 제목 · 한 줄 설명을 넣습니다
3. 아래 두 가지 중 **하나만** 고릅니다
   - **HTML 파일 올리기** 탭 → 파일 선택
   - **링크 주소 넣기** 탭 → `https://` 로 시작하는 주소 입력
4. **올리기** 를 누르면 아래 목록에 바로 추가됩니다
5. 제목을 누르면 새 탭에서 열립니다. 목록의 **×** 를 누르면 삭제됩니다 (비밀번호 확인)

목록에서 파일로 올린 것은 **H**, 링크로 올린 것은 **🔗** 아이콘으로 구분됩니다.

제한: HTML 파일 1개, 5MB 이하. 링크는 `http://` 또는 `https://` 로 시작하는 주소만 등록됩니다.

> 발표 자료를 열면 화면 맨 위에 "이 애플리케이션은 Google Apps Script 사용자가 만들었습니다"라는 구글 안내 띠가 뜹니다.
> 구글이 자동으로 붙이는 것이라 없앨 수 없습니다. 오른쪽 **×** 로 닫고 보시면 됩니다.

## 코드를 고친 뒤에는

Apps Script 코드를 수정했다면 **`배포` → `배포 관리` → 연필(수정) → 버전 `새 버전` → `배포`** 를 해야 반영됩니다.
이렇게 하면 웹 앱 주소는 그대로 유지되므로 홈페이지는 손댈 필요가 없습니다.
(`새 배포`를 누르면 주소가 새로 생기니 주의하세요.)

## 자주 겪는 문제

| 증상 | 확인할 것 |
|---|---|
| 목록이 안 뜨고 "불러오지 못했습니다" | 배포 시 **액세스 권한 = 모든 사용자** 였는지, URL이 `/exec` 로 끝나는지 |
| 업로드 시 "비밀번호가 일치하지 않습니다" | `.gs` 파일 위쪽 `var 비밀번호 = '0625';` 와 `index.html` 의 비밀번호가 같은지 |
| 링크를 넣었는데 "HTML 파일이나 링크 주소 중 하나는 있어야 합니다" | Apps Script 코드가 옛 버전입니다. `.gs` 파일을 다시 붙여넣고 **`배포 관리` → 수정 → 새 버전** 으로 재배포하세요 |
| 파일은 올라갔는데 화면이 깨짐 | 올린 HTML이 외부 파일(css/js)을 상대경로로 참조하는 경우입니다. 한 파일 안에 스타일·스크립트가 모두 들어간 HTML로 만들어 올려주세요 |
| 코드를 고쳤는데 그대로임 | `새 배포`가 아니라 **`배포 관리` → 수정 → 새 버전** 으로 다시 배포 |

## 보안에 대한 참고

- 비밀번호(`0625`)는 브라우저에서 볼 수 있는 값이라 **외부인 차단용 잠금장치는 아닙니다.** 내부 직원용 구분 정도로 보시면 됩니다.
- 업로드된 HTML은 구글이 제공하는 별도 도메인(googleusercontent.com)의 격리된 화면에서 열리므로, 본 홈페이지에는 영향을 주지 않습니다.
- 배포 액세스를 **"조직 내 사용자"** 로 바꾸면 이 방식은 **동작하지 않습니다.** 홈페이지에서 목록·업로드를 `fetch` 로 통신하는데, 다른 도메인에서 보내는 요청에는 구글 로그인 쿠키가 실리지 않아 매번 로그인 화면으로 넘어갑니다. 직원이 회사 계정으로 로그인해 둬도 마찬가지입니다.
- 더 엄격한 통제가 필요하다면 구글 방식이 아니라 별도 인증을 둔 다른 구조로 바꿔야 합니다.
